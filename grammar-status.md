# Kanagawa grammar status (Rust frontend)

This document tracks the current implementation/testing status of the Rust frontend grammar work against:

- Canonical language notes: [grammar.md](grammar.md)
- Canonical parser implementation: [compiler/hs/lib/Language/Kanagawa/Parser.hs](compiler/hs/lib/Language/Kanagawa/Parser.hs) and [compiler/hs/lib/Language/Kanagawa/Parser/Lexer.hs](compiler/hs/lib/Language/Kanagawa/Parser/Lexer.hs)
- Editor-oriented (approximate) grammar: [tools/editors/vscode-new/grammar/grammar.js](tools/editors/vscode-new/grammar/grammar.js)

Rust frontend scope today:

- Implemented: lossless lexer + CST builder (rowan) and a permissive “shape-first” parser.
- Not implemented yet: full AST, semantic validation/type checking, CST→ParseTree lowering via the C ABI.

## Legend

- **Working**: produces dedicated CST nodes (not just tokens) and is covered by unit tests and/or harness parsing.
- **Partial**: lexed correctly and/or parsed only as a balanced token region; limited structure/validation.
- **Missing**: not specially recognized/structured yet (may still appear as raw tokens).

Evidence is primarily under [compiler/rs/crates/kanagawa_syntax/tests/](compiler/rs/crates/kanagawa_syntax/tests/).

## High-level status

- **Lexer**: Working (keywords/operators/comments/literals across repo corpus)
- **Top-level/module/import**: Working (shape-first)
- **Attributes (`[[...]]`)**: Working (generic blocks; not semantically categorized)
- **Declarations**: Working for the common surface forms (shape-first)
- **Statements**: Working for the common statement forms (shape-first)
- **Types**: Working (dedicated `Type` CST with templates/arrays/function types; permissive)
- **Expressions**: Working (precedence-aware CST via Pratt parser; permissive)

## 8) Tree-sitter-only or mismatch surface

The editor grammar intentionally accepts some constructs for UX and may diverge from the canonical compiler parser.

Examples (non-exhaustive):

- `continue` and `protected` appear in tree-sitter keyword lists, but are not in the canonical reserved list in [compiler/hs/lib/Language/Kanagawa/Parser/Lexer.hs](compiler/hs/lib/Language/Kanagawa/Parser/Lexer.hs).
- `inspectable(...)` is modeled as a declaration in [tools/editors/vscode-new/grammar/grammar.js](tools/editors/vscode-new/grammar/grammar.js); it does not appear in the canonical Haskell parser.

## 9) What’s next (front-end milestones)

- Expand structured CST coverage and tests for:
  - remaining statement/decl forms still in shape-first mode (notably `unrolled_for`)
  - more expression term forms (builtin spellings, offsets, and other canonical `term` variants)
  - deeper type CST assertions (arrays/function/decltype/typename) beyond harness-only coverage
- Add a typed AST layer and begin CST→AST lowering.
- Implement AST→ParseTree emission using the existing C ABI seam (see [compiler/cpp/parse_tree.h](compiler/cpp/parse_tree.h)).
